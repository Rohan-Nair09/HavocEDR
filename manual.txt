EXPERIMENT – 1 
Identify Project Problem Statement and Define Project Objectives 
Aim 
To identify the cybersecurity problem addressed by the project and define clear objectives for 
developing an intelligent Endpoint Detection and Response (EDR) system capable of 
monitoring endpoint activities, detecting threats, and assisting users in security incident 
response. 
Objectives 
 To study cybersecurity challenges associated with Windows endpoints. 
 To identify limitations of traditional security solutions. 
 To formulate a well-defined project problem statement. 
 To establish the scope of the proposed system. 
 To define measurable objectives for the development of HavocGuard EDR. 
 To provide a foundation for the design and implementation phases of the project. 
Introduction 
In today's digital world, organizations and individuals depend heavily on computer systems for 
communication, data storage, financial transactions, and business operations. As the use of 
technology increases, cyber threats continue to evolve in both frequency and sophistication. 
Attackers frequently target endpoint devices such as desktops, laptops, and workstations 
because they serve as entry points into larger systems and networks. 
Windows operating systems generate a large amount of system activity including process 
creation, file modifications, registry changes, network connections, and service executions. 
Monitoring these activities manually is difficult due to the volume of data generated every 
second. As a result, suspicious behaviour may remain unnoticed until significant damage has 
already occurred. 
Traditional antivirus solutions mainly focus on signature-based detection and often struggle to 
detect advanced threats, zero-day attacks, insider threats, and suspicious behavioural patterns. 
This creates a need for intelligent monitoring systems capable of continuously observing 
endpoint activities, identifying anomalies, and assisting users in understanding potential 
security incidents. 
To address these challenges, the project "HavocGuard EDR: An AI-Powered Endpoint 
Detection and Response System for Windows" is proposed. The system combines endpoint 
monitoring, threat detection, Machine Learning analysis, and AI-assisted security 
recommendations within a unified desktop application. 

 
 
 
 
 
 
 
Problem Identification 
Endpoint devices are continuously exposed to a variety of security risks including malware 
infections, unauthorized access attempts, suspicious process execution, malicious scripts, 
registry manipulation, and abnormal network communications. 
Several challenges were identified during the problem analysis stage: 
1. Lack of Real-Time Endpoint Visibility 
Users often have limited visibility into processes, services, registry modifications, and network 
activities occurring on their systems. 
2. Increasing Complexity of Cyber Threats 
Modern attacks frequently employ sophisticated techniques that bypass traditional signature-
based security tools. 
3. Difficulty in Threat Analysis 
Security alerts often contain technical information that may be difficult for users to understand 
and interpret. 
4. Delayed Incident Response 
Without proper monitoring and analysis mechanisms, suspicious activities may remain 
undetected for extended periods. 
5. Limited Accessibility of EDR Solutions 
Many commercial Endpoint Detection and Response solutions are expensive and primarily 
designed for enterprise environments, making them less accessible for educational and research 
purposes. 
Problem Statement 
Current security solutions often fail to provide comprehensive visibility into endpoint activities 
and may struggle to identify emerging threats through behavioural analysis. Users frequently 
lack the tools required to monitor system activities, detect suspicious behaviour, understand 
security alerts, and respond effectively to incidents. 
Therefore, there is a need to develop a lightweight and intelligent Endpoint Detection and 
Response system that continuously monitors endpoint activities, detects suspicious behaviour, 
generates security alerts, and provides AI-assisted recommendations to improve threat analysis 
and incident response. 

 
 
 
 
 
 
 
Proposed Solution 
The proposed solution is HavocGuard EDR, a Windows-based Endpoint Detection and 
Response system designed to provide continuous monitoring and intelligent threat detection 
capabilities. 
The system will: 
 Monitor processes and services. 
 Track network activities. 
 Monitor file integrity and registry modifications. 
 Collect Windows endpoint telemetry. 
 Detect suspicious behaviour using rule-based techniques. 
 Apply Machine Learning models for anomaly detection. 
 Generate security alerts and threat scores. 
 Provide AI-generated explanations and mitigation recommendations. 
 Present monitoring information through an interactive dashboard. 
This approach enables users to gain better visibility into endpoint activities while simplifying 
threat analysis and response. 
Project Objectives 
The primary objectives of HavocGuard EDR are: 
1. Endpoint Monitoring 
To continuously monitor endpoint activities including processes, services, files, registry 
entries, and network connections. 
2. Threat Detection 
To identify suspicious behaviour using predefined detection rules and behavioural analysis 
techniques. 
3. Machine Learning Integration 
To improve threat detection accuracy through Machine Learning-based analysis of endpoint 
telemetry. 
4. AI-Assisted Security Analysis 
To provide understandable explanations of detected threats using Generative AI. 
5. Security Alert Generation 

 
 
 
 
 
 
 
To notify users when suspicious activities or potential threats are detected. 
6. Incident Response Support 
To assist users in making informed decisions regarding threat mitigation and response actions. 
7. Security Reporting 
To generate reports and analytics for security monitoring and investigation purposes. 
Scope of the Project 
The scope of HavocGuard EDR includes: 
 Windows endpoint monitoring. 
 Process and service monitoring. 
 Network connection monitoring. 
 Registry activity monitoring. 
 File integrity monitoring. 
 Threat detection and alert generation. 
 AI-assisted security recommendations. 
 Dashboard visualization and reporting. 
The project focuses on Windows-based systems and does not include enterprise-scale 
centralized management features. 
Expected Outcomes 
The successful completion of the project is expected to result in: 
 A functional Endpoint Detection and Response application. 
 Improved visibility into endpoint activities. 
 Faster detection of suspicious behaviour. 
 Enhanced understanding of security incidents. 
 AI-assisted threat analysis and recommendations. 
 Practical implementation of cybersecurity, Machine Learning, and software 
engineering concepts. 
Observation 
The analysis of endpoint security challenges revealed the importance of continuous monitoring 
and behavioural analysis in detecting modern cyber threats. Existing security tools may not 
always provide sufficient visibility or understandable threat explanations. These observations 
justified the need for developing an intelligent endpoint monitoring solution. 

 
 
 
 
 
 
 
Result 
The project problem statement was successfully identified, and clear objectives were defined 
for the development of HavocGuard EDR. The identified requirements, scope, and objectives 
provide a structured foundation for the design, implementation, testing, and deployment phases 
of the project.

A Software Requirement Specification (SRS) is a formal document that describes the

a blueprint for software development by clearly defining what the system should accomplish 
before implementation begins. 
 
For HavocGuard EDR, the SRS was prepared by analyzing modern Endpoint Detection and 
Response (EDR) solutions and Windows security mechanisms. The document includes the 
project scope, system architecture, functional requirements, non-functional requirements, user 
interface requirements, workflow, and technology stack. A well-structured SRS helps reduce 
development errors, improves communication among stakeholders, and serves as a reference 
throughout the software development life cycle. 
 
1. Introduction 
HavocGuard EDR is a Windows-based Endpoint Detection and Response system designed to 
monitor endpoint activities, detect suspicious behavior, and assist users in responding to 
cybersecurity threats. The application combines Rule-Based Detection, Machine Learning, and 
Generative AI to provide intelligent threat detection and simplified security analysis. 
The primary goal of the project is to enhance endpoint visibility, improve threat detection 
accuracy, and provide AI-assisted recommendations for responding to security incidents. 
 
2. Overall Description 
The system continuously monitors Windows endpoint activities and collects telemetry from 
various monitoring modules. It analyses the collected information using predefined detection 
rules and Machine Learning algorithms to identify suspicious behavior. When a threat is 
detected, the system generates security alerts, calculates a threat score, and recommends 
appropriate mitigation actions using the AI Security Analyst. 
 
The application is intended for students, researchers, cybersecurity enthusiasts, and system 

 
 
 
 
 
 
 
administrators who require a lightweight endpoint monitoring solution.

 Security Report Generation  
 
4. Non-Functional Requirements

 Near real-time monitoring

 User-friendly desktop interface  
 Reliable and accurate threat detection  
 Modular architecture for future enhancements

5. System Architecture 
HavocGuard EDR follows a modular architecture consisting of multiple monitoring modules, 
a telemetry collection engine, a threat detection engine, a Machine Learning model, an Incident 
Response Engine, an AI Security Analyst, and a desktop dashboard. Each module performs a 
dedicated task while communicating through a centralized SQLite database. 
 
6. System Workflow 
The workflow begins with the background monitoring agent collecting telemetry from running 
processes, services, registry activities, files, USB devices, and network connections. The 
collected telemetry is stored in the SQLite database and analyzed by the Rule-Based Detection 
Engine and Machine Learning model. 
 
If suspicious behavior is detected, the system calculates a threat score and generates an alert. 
Depending on the configured response mode, the system either monitors the event, asks the 
user for confirmation, or automatically performs the selected response action. Finally, the AI 
Security Analyst generates a threat explanation and recommended mitigation steps.

Theory 
System architecture represents the overall structure of a software application and defines how 
different modules communicate with each other. A well-designed architecture improves 
maintainability, scalability, and performance. 
 
The workflow diagram illustrates the sequence of operations performed by the application from 
data collection to threat detection and response. It helps developers understand how 
information flows through the system and ensures that each module functions in the correct

For HavocGuard EDR, a modular architecture was adopted to separate monitoring, detection, 
response, and reporting functionalities. This modular approach simplifies maintenance and 
allows future enhancements without affecting the entire application. 
 
System Architecture 
The architecture of HavocGuard EDR consists of the following major modules: 
 HavocAgent – Collects endpoint telemetry.  
 Monitoring Modules – Monitor processes, services, files, registry, USB devices, and 
network activities.  
 Telemetry Collection Engine – Collects and stores endpoint events.  
 SQLite Database – Stores logs, alerts, and system data.  
 Threat Detection Engine – Performs rule-based detection and Machine Learning 
analysis.  
 Incident Response Engine – Executes monitoring or response actions.  
 AI Security Analyst – Generates threat explanations and mitigation recommendations.  
 Desktop Dashboard – Displays monitoring information, alerts, and reports.  

 
 
 
 
 
 
 
 
 
Workflow 
The workflow of HavocGuard EDR begins when the monitoring agent starts collecting 
endpoint telemetry from various monitoring modules. The collected data is stored in the SQLite 
database and analyzed by the Rule-Based Detection Engine and Machine Learning model. 
 
If suspicious behavior is detected, the system calculates a threat score and generates a security 
alert. Depending on the selected response mode, the application either monitors the activity, 
requests user confirmation, or automatically performs the configured response action. Finally, 
the AI Security Analyst generates a detailed explanation of the detected threat and suggests 
mitigation steps to assist the user.
